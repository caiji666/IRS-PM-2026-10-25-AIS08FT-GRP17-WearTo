## JSON handoff

The module returns `ModuleResult` with `status`, `data`, `reason`. After handling `needs_input`/`error`, read context from `result["data"]`. The added single-season property is `result["data"]["season"]`; provenance and multiple-season cases are in `season_context`. `trip_request` continues to contain user facts only.

Single season: spring/summer/autumn/winter. Unknown/unsupported/multiple seasons: null. Do not substitute `weather_class` for season, and do not invent a fallback when season is null. A receiver generating search queries can omit the season token or create one query per supported season. The current registry has seven cities; other destinations need confirmed/provider coordinates. Review the location defaults and conservative tropical scope policy with the team.

The final text is `result["data"]["expanded_fashion_context"]`. Clothing and activity requirements, evidence and budget/exclusions remain separate structured fields. No FashionCLIP embedding is generated by Student 1 yet.

## LangChain boundary

`understand_and_reason` is decorated with LangChain `@tool` and registered in `agent.py`'s shared tool list. `build_agent(model)` uses `create_agent`; the main agent model is configured by its caller. Local Qwen extraction uses Transformers/PyTorch directly and is not automatically the main tool-calling agent model.

The service and CLI can run directly, which makes the reasoning independently testable. Other contributors' four tools still return `not_implemented` in this checkout. The tests verify tool wrappers and module logic; a live autonomous multi-tool recommendation agent has not been verified.

Known limitations remain: Qwen errors, human extraction review, pending KG/weather/season-rule review, untested live Neo4j and unimplemented downstream recommendation modules. Real-model baseline metrics and failures are retained in `evaluation/results/`.
