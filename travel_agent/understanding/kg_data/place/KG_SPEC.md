规范版本：1.1.0  
生效日期：2026-10-07  
兼容的数据 Schema：0.1.1（原始v0.1原则及已登记扩展）  
适用范围：`student1/place_kg/`，以及为本KG采集、整理、导入或生成的数据。

## 1. 规范地位与变更边界

本文件是本KG唯一的规范性文档。后续每次查找新资料、追加国家、修改数据、生成规则和导出图谱，必须先阅读本文件，再阅读相关受控词表与现有数据。README、国家清单、查询示例是使用说明或派生产物，不能独立改变规范。

原始需求保留在 `schema_input.txt`，不得改写。该文件中的示例规则是设计示意，不能代替真实场所证据；本规范继承其六项设计原则，并固定当前项目已明确的适用条件与扩展边界。

**只允许在现有规范上做兼容扩充，不得因新国家或新来源另建不兼容Schema。**

- 可以追加有据可查的数据、通用词表条目、可选字段和关系；先登记扩展，再写依赖它的数据。
- 不得删除或改名既有字段、实体类型、关系或受控标签；不得改变既有ID的指代和字段语义。
- 不得把可空字段改为必填，不得收紧层级导致已有合法国家数据失效，不得静默改变字段类型、单位或规则作用范围。
- 新概念优先复用已有概念；确需扩展时，必须说明定义、适用范围、证据、兼容性与验证方式。
- 发现事实错误可以更正数据；保留原记录快照及更正依据，不能以“追加”为由保留已知错误，也不能借更正之名改变Schema。重复实体合并必须保留旧ID映射。
- 若业务要求与既有规范冲突，应说明冲突并等待用户明确修改规范；不得自行绕过、重写旧条款或创建平行规范。

## 2. 不变的六项原则

1. **统一Place**：国家、区域、城市、区、城镇和POI均为Place，通过place_type与part_of表达区别，不按国家或行政级别另建实体表。
2. **规则与地点解耦**：地点描述事实和可选活动；Rule根据共用标签推出Requirement，再关联ItemCategory。具体场所的正式要求使用place_dresscode并保留条件。
3. **气候标签驱动**：气象数值用于生成受控标签，衣物规则使用标签。数值、阈值、来源和推断必须可区分。
4. **词表先行**：标签只能来自data/vocabulary.json；新增条目按第8节登记，不允许抽取时自由造标签。
5. **逐条溯源**：节点、关系与规则均保留source、confidence、updated_at，以及当前项目的basis、evidence、review_status、reviewed_by。
6. **月份可空**：month为空可以表示来源支持的全年档案；不得把月份未知的季节数据解释为全年适用。

## 3. 共用实体与存储约定

运行时数据源是 `data/*.csv`；CSV使用UTF-8，可带BOM，空单元格表示缺失，不表示0或False。JSON/Cypher导出将空值转为null，列表字段以分号分隔，布尔值为True/False。不得在列表值内部混用自由文本标签。

| 实体 | 共用表 | 标识及职责 |
|---|---|---|
| Place | places.csv | place_id；地点类型、父级、名称与环境事实 |
| Alias | aliases.csv | alias_id，place_id；多语言别名，不能作为新地点复制依据 |
| ClimateProfile | climate.csv | climate_id，place_id；月份、气象数值、标签、档案类型与继承范围 |
| SeasonEvent | season_events.csv | event_id，place_id；起止月份、季节事件与标签 |
| Activity | activities.csv | activity_id；国家无关的活动语义 |
| Requirement | requirements.csv | req_id；温度、防护、礼仪、舒适或功能需求 |
| Rule | rules.csv | rule_id；条件、强度与推出的需求 |
| Style | styles.csv | style_id；可选风格，不能伪装成服装规定 |
| ItemCategory | items.csv | item_id；候选单品及属性，不代表实际商品已经满足需求 |
| Content | contents.csv | content_id；来源摘要、地点、标签和版权说明 |
| Source | sources.csv | source_id；来源URL、性质、读取等级与访问日期 |

既有CSV完整表头是当前字段接口；新字段只能以可空字段追加，并在本文件扩展记录中登记。不得删除现有溯源、审核或条件字段。已有字段的类型转换见export.py；实现与本规范不一致时，应修复实现并记录，不能反向静默改规范。

### 3.1 Place约束

- 必须有唯一place_id、名称、place_type、country_code及溯源。优先使用已核实的Wikidata QID；未核实采用稳定local:ID。ID是不透明标识，查询不得解析其中的jp、pref等字样来判断语义。
- name_zh、name_en、name_local保存名称；中文项目译名须说明，未知本地名称留空。别名歧义不得自动选中某一个地点。
- part_of指向已有Place；不得成环。当前模型是单国归属树，父链国家一致，最终到达country；country无父节点。跨境或多父级地理不是当前模型能力，需先设计兼容扩展。
- 不强制“国家→省→市→区→景点”固定层数。城市国家可以直接挂POI，不补虚构行政节点。
- region表示地理/旅游区域或省州等范围，不承诺固定行政级别；part_of是本项目的地理归属，不自动声称法律行政隶属。
- lat/lon仅使用已核实坐标；缺失留空，不用国家/城市中心点假冒景点坐标。popularity无可信口径则留空。
- indoor_outdoor取indoor/outdoor/mixed，walk_intensity取1–3或空；ground_tags、environment_tags使用受控词表。无法确认不猜填。
- is_destination区分可展开的游览目的地与地理容器；不能仅因是Place就自动展开为行程。

### 3.2 已登记的通用扩展

以下是原始v0.1之外已采用的通用概念，适用于所有国家；不是国家专用类别。定义集中在schema.py，并注册到data/vocabulary.json。

| 条目 | 定义与边界 |
|---|---|
| region | 地理、旅游或省州等区域，不隐含行政级别 |
| town | 城镇级聚落，不仅指日本的町 |
| poi_heritage | 城堡、宫殿、古城或遗址等历史游览地 |
| poi_shrine | 神祠类宗教场所，不隐含特定宗教、国家或着装规定 |
| poi_aquarium | 水族馆，不隐含涉水、低温或服装要求 |
| aquarium_visit | 水族馆展览参观活动，与beach等活动分开 |

其余现有受控值以data/vocabulary.json为完整登记表；这些已登记值受本规范的兼容性保护。任何新增值都必须同步更新该表和本文件扩展记录。

## 4. 共用关系与推理边界

| 关系/表 | 语义与约束 |
|---|---|
| part_of | Place地理父链，允许不同国家有不同深度 |
| has_activity / place_activity.csv | 可选活动；selection_required保留，不视为用户已确定参加 |
| has_dresscode / place_dresscode.csv | 具体场所要求，保留入内区域、性别分支、强度与证据 |
| has_climate、has_event | 地点对应的气候档案或季节事件，查询时按范围和月份过滤 |
| requires、implies / rules.csv | 活动/气候标签推出需求；Rule单独存表，导出边不能绕过条件过滤 |
| satisfied_by / requirement_item.csv | 需求对应候选单品，组合、长度、透明度等属性仍需核验 |
| has_style、composed_of | 风格与组成，只做可选信息 |
| mentions_place、mentions_item、has_style | Content关联；缺乏内容证据时不补造关系 |
| sourced_from | 节点/关系的来源引用；不得只在整批说明中笼统写来源 |

- must用于有依据的强制要求；should为建议，nice为可选。不能把舒适性建议升级为场所规定。
- 不允许“在某国→必须某穿法”这类无来源规则；同一活动应共用同一规则ID。
- 宗教类型不自动推出普遍遮肩、脱鞋等规则；场所证据优先，未知标未知。
- 进入室内、怕冷、性别分支等条件必须保留。未知条件应返回待确认分支，不能推定成立。
- 只参拜不等于登山；到温泉街不等于入浴；在公园不等于进入其中某个博物馆。无法明确子场馆时保留资料缺口。
- 若某活动暂无规则，应返回无匹配需求/待补信息，不能为了丰富输出编造衣物需求。

## 5. 天气与环境

当前工作约定：新地点采集不继续补静态天气，天气API由后续任务接入；保留已有ClimateProfile，不能宣称已经查询实时天气。

- 长期气候常态、季节事件、实时预报与室内环境必须区分，不能混用。
- 后续API至少需明确地点、具体日期或时间范围、单位和来源，再转换成通用标签；仅“8月日本”不足以构成具体日期预报。
- 城市天气不得无条件继承到山地；室外气候不得当作馆内温度。继承必须由范围与inherit_to_descendants等现有条件控制。
- 没有天气数据时返回缺失；仍可根据已选活动推导有据可查的非天气需求。
- 不推定所有室内场所都有强冷气，不因水族馆的展缸温度推断游客区域温度。

## 6. 资料采集与审核

优先场馆、政府、官方旅游机构等一手来源。其他来源可登记，但来源性质和可信度不得冒充官方。

每条新事实必须有可追溯来源；检索摘要、读取正文和项目推断分别记录。搜索摘要不能标为已阅读正文；官网访问失败要如实记录。访问日期与发布日期分开，发布时间未知留空。

- evidence保存简短证据概括或章节定位，Content保存项目摘要与原链接，不搬运全文或图片。
- 翻译、分类、活动归一化、阈值和单品映射属于项目整理/推断，要通过basis等字段说明。
- confidence是证据强度估计，不是统计概率，也不是人工审核结果。
- 新采集记录默认pending；不得自行伪造approved或reviewed_by。已有审核状态不得在重跑导入时被重置。
- 时间敏感条款、票价、开放时间不能用旧页推断当前事实；本KG不需要的字段不为“完整”而填充。
- 缺少证据的资料进入review_queue.json，不填充到事实字段；国家覆盖率不等于事实正确率或推荐质量。

## 7. 每次采集后的必做流程

1. 阅读本文件、vocabulary.json、目标地点及别名，确认可复用概念并去重。
2. 检索和核对来源，先登记Source，再补Place、Alias及有证据的活动关系/摘要。
3. 如需新概念，先执行第8节；未登记前不得写入新标签或国家专用字段。
4. 以增量方式写入共用CSV，保留现有ID、记录和审核状态。不得用build_seed.py覆盖当前工作数据。
5. 执行结构检查和现有测试；有新规则、解析或层级行为时增加相应回归测试。纯文字修改检查文档一致性即可。
6. 数据变化后重新生成图谱、覆盖清单和受影响查询示例；确认派生文件与CSV一致。生成Neo4j文件不等于已导入数据库。
7. 更新本文件维护记录、资料缺口和受影响说明。交付时报告增量、验证结果与未核实部分。

常用命令（项目根目录执行）：

```sh
python3 -m student1.place_kg.validate
python3 -m unittest discover -s student1/place_kg/tests
python3 -m student1.place_kg.export
python3 -m student1.place_kg.make_examples
```

还应重跑受影响的country_month示例；覆盖国家、地点数量等变化不能只更新说明而不更新示例。旧归档必须明确是旧快照，不能作为当前数据交付。

## 8. 只增不破坏的扩展流程

扩展须在同一次修改中完成以下事项：

1. 在下表追加记录：编号、日期、动机、名称、定义/类型/单位、可空性/默认值、作用范围、来源或项目建模依据、兼容性及验证。
2. 先搜索已有概念，说明为什么不能复用；定义必须跨国家，不以某批资料的名字替代通用语义。
3. 更新本文件对应条款，以增加条款或明确补充为主；保留既有语义和历史记录。
4. 同步词表、schema.py（如涉及通用词表扩展）、数据生成器、读取/导出/校验器及测试；新字段缺失时旧数据仍须可读。
5. 验证已有国家与查询仍可用，再导入依赖新概念的数据。扩展不能以修改旧测试期待值掩盖原功能退化。

文档版本独立于数据Schema版本：新增兼容规范用次版本，文字澄清用修订版本；若机器接口发生扩充，另行登记Schema版本并同步实现元数据。不得用版本号变化为破坏性变更自动授权。

## 10. 人工审核工具（EXT-003，2026-10-07）

用户已确认本地HTML＋Python单人审核方案。本节为兼容扩充，原CSV字段与Schema版本保持不变。

- 审核入口按地点聚合，但决定以表名＋主键/组合键标识的单条记录为单位，不使用CSV行号。关联记录不连带批准。
- 保存决定只写reviews/review.sqlite3。通过、需补证据、拒绝、修改草稿、撤销草稿分别对应approve、needs_evidence、reject、edit、cancel；应用后CSV仍仅使用approved/pending/rejected三种状态。
- 每次操作追加审核人、时间、理由、证据定位、旧快照、修改内容、内容指纹、规范版本与规范指纹。历史不删除；后续决定取代旧待应用决定，但历史保留。
- 改动现有数据字段后回到pending，必须重新阅读并批准修改后的记录；禁止同时改事实并通过。主键、审核字段与新增词表不可在通用表单中随意改动。
- 应用前展示明确差异和校验结果；预览标识绑定输入文件与最新决定。数据或规范在预览后变化则必须重新预览。
- 应用通过暂存目录生成并校验全套受影响产物，保存备份和恢复日志，写回失败回滚；中断重启先恢复再服务。外部程序直接并发修改CSV不受本工具锁保护，检测到冲突停止处理。
- 已批准记录的内容与本工具最近批准版本不一致时显示stale；查询审核模式排除该记录，历史仍保留。来源或父级变化也会通过依赖链显示待复核。外部历史批准无本工具快照时显示untracked，不算审核链完整。
- 查询页面的“严格审核模式”必须检查源记录、父级、活动/规则/需求/单品、别名和来源依赖。草稿输出仍可查看，但不能标为整条已审核；其他历史CLI不因此自动变成严格模式。
- reviews中的SQLite、备份、导出是审核元数据，不是新KG实体表；审核结果只经明确应用操作写回CSV。服务仅监听本机，不进行自动网页采集、不代替人点击通过。
- 事实可信与资料齐全分开显示；天气缺口留待后续API，来源打不开可记需补证据。来源通过不自动批准引用它的事实。
