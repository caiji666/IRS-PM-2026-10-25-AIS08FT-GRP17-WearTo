## 1. Overview

The Inspiration module retrieves and ranks fashion reference images based on travel requirements generated by the Student 1 Understanding module.

It uses **FashionCLIP** to represent the user's expanded fashion context and retrieved fashion images in a shared 512-dimensional embedding space. Cosine similarity is then used to rank the retrieved images according to their relevance to the fashion context.

The module supports:

- Structured fashion search query generation.
- Unsplash API image retrieval.
- Image deduplication using Unsplash image IDs.
- Image downloading and preprocessing.
- FashionCLIP text and image embedding generation.
- L2-normalized cosine similarity ranking.
- Top-N fashion inspiration selection.
- Evaluation data collection.
- File-based handoff to Student 3's product retrieval pipeline.
- Integration with the shared LangChain agent through `service.py` and `tools.py`.

The module does not perform product retrieval, outfit generation, budget validation, or final recommendation.

The reusable pipeline is implemented in:



## 4. Student 1 Input Contract

Student 2 receives fashion context information produced by the Student 1 Understanding module.

The required fields are obtained from Student 1's `ModuleResult.data`.

| Student 2 input | Student 1 source |
|---|---|
| Expanded fashion context | `expanded_fashion_context` |
| Destination | `trip_request.destination` |
| Season | `season` |
| Weather clothing requirements | `weather_clothing_requirements` |
| Activity style requirements | `activity_style_requirements` |
| User style preferences | `trip_request.style` |
| Downstream readiness | `ready_for_downstream` |

### 4.1 Context adaptation

The adapter is implemented in:

`travel_agent/inspiration/service.py`

```python
def prepare_inspiration_context(data: dict) -> tuple[str, dict]:
    trip_request = data["trip_request"]

    expanded_context = data["expanded_fashion_context"]

    structured_context = {
        "destination": trip_request["destination"],
        "season": data["season"],
        "weather_clothing_requirements": data["weather_clothing_requirements"],
        "activity_style_requirements": data["activity_style_requirements"],
        "user_style": trip_request.get("style", []),
    }

    return expanded_context, structured_context
```

The expanded context is used for FashionCLIP text embedding generation.

The structured context is used for search query generation.

Student 1's `ready_for_downstream` flag must be true before the inspiration service proceeds. A partial context may still be usable when no mandatory clarification questions remain.

### 4.2 Example structured context

```json
{
  "destination": "Seoul",
  "season": "winter",
  "weather_clothing_requirements": {
    "outerwear": ["winter coat", "puffer jacket"],
    "top": ["sweater"],
    "bottom": ["long trousers"],
    "footwear": ["boots"],
    "properties": ["warm"]
  },
  "activity_style_requirements": {
    "sightseeing": ["casual", "comfortable"],
    "dinner": ["smart casual", "polished"]
  },
  "user_style": ["minimalist"]
}
```

The weather clothing requirements are compatible with Student 1's `WeatherClothingRequirements` schema.

The activity style requirements map activity names to lists of occasion or functional style directions.

## 5. FashionCLIP Model Configuration

The module uses the pretrained FashionCLIP checkpoint:

| Parameter | Value |
|---|---|
| Model ID | `patrickjohncyh/fashion-clip` |
| Model revision | `7e3ba62ce16b379a1ab479346b66f192e76f51b7` |
| Transformers version | `4.57.6` |
| Text hidden dimension | 512 |
| Vision hidden dimension | 768 |
| Projection dimension | 512 |
| Normalization | L2 |
| Preprocessing identifier | `clip-rgb-exif-text77-v1` |

Model initialization:

```python
model = CLIPModel.from_pretrained(MODEL_NAME, revision=MODEL_REVISION)

processor = CLIPProcessor.from_pretrained(MODEL_NAME, revision=MODEL_REVISION, use_fast=False)

model.eval()
```

The slow image processor is selected explicitly for reproducibility.

The preprocessing identifier is metadata used for compatibility tracking. Actual compatibility also depends on the implemented preprocessing operations.

### 5.1 Text embeddings

The expanded fashion context is tokenized using the FashionCLIP processor.

Projected text features are generated using:

```python
with torch.inference_mode():
    context_embedding = model.get_text_features(**text_inputs)
```

The resulting embedding is L2-normalized.

Expected shape:

`[1, 512]`

### 5.2 Image embeddings

Downloaded images are prepared as RGB images, with EXIF orientation correction where implemented.

The FashionCLIP processor converts images into model-compatible pixel inputs.

Projected image features are generated using:

```python
with torch.inference_mode():
    batch_embeddings = model.get_image_features(**image_inputs)
```

Embeddings are generated in batches and normalized using:

```python
batch_embeddings = batch_embeddings / batch_embeddings.norm(dim=-1, keepdim=True).clamp_min(1e-12)
```

The resulting batches are transferred to CPU memory and concatenated.

Expected shape:

`[N, 512]`

where `N` is the number of successfully loaded images.

## 6. Unsplash Image Retrieval

The query generator uses destination, season, weather clothing requirements, activity requirements, and user style preferences to generate targeted search queries.

Example queries:

```text
Seoul winter minimalist outfit
Seoul winter sightseeing casual comfortable outfit
Seoul winter dinner smart casual polished outfit
Seoul winter winter coat outfit
Seoul winter puffer jacket outfit
Seoul winter sweater long trousers boots outfit
```

Images are retrieved through the Unsplash API.

### 6.1 API configuration

Create a local `.env` file in the repository root:

```dotenv
UNSPLASH_ACCESS_KEY=your_unsplash_access_key
```

Do not commit API keys or the `.env` file.

The retrieval module reads the key from the environment.

### 6.2 Retrieval parameters

The pipeline supports:

| Parameter | Default | Purpose |
|---|---|---|
| `top_n` | 10 | Maximum number of ranked images returned |
| `max_queries` | `None` | Maximum number of generated queries executed |
| `per_page` | 30 | Maximum results requested per Unsplash query |

For limited testing:

```python
run_inspiration_pipeline(
    expanded_context=expanded_context,
    structured_context=structured_context,
    top_n=10,
    max_queries=1,
    per_page=5,
)
```

For normal execution, `max_queries=None` uses all generated queries.

### 6.3 Deduplication

Retrieved images are deduplicated using their unique Unsplash image IDs.

The pipeline retains the original retrieval order after deduplication.

The `original_rank` field is recorded before image loading, preserving the initial candidate order even when individual image downloads fail.

## 7. Image Ranking and Top-N Selection

FashionCLIP text and image embeddings are L2-normalized.

Cosine similarity is used to compare the context embedding with each image embedding.

For normalized vectors, cosine similarity is equivalent to their dot product.

Images are sorted by descending similarity score.

The pipeline selects up to `top_n` images.

If fewer than `top_n` valid images are available, all available images are returned.

### 7.1 Metadata alignment

The selected image records and embeddings must remain aligned:

```text
top_images[0] <-> top_image_embeddings[0]
top_images[1] <-> top_image_embeddings[1]
top_images[2] <-> top_image_embeddings[2]
...
```

This ordering is preserved when generating the Phase 2 output and when Student 3 loads the upstream artifacts.

## 8. Pipeline Outputs

### 8.1 Phase 2 output

The pipeline returns:

```python
phase2_output = {
    "context_embedding": context_embedding.cpu(),
    "top_images": top_images,
    "top_image_embeddings": top_image_embeddings,
}
```

| Field | Description |
|---|---|
| `context_embedding` | L2-normalized FashionCLIP context embedding |
| `top_images` | Ranked image metadata, including image identifiers and URLs |
| `top_image_embeddings` | Aligned FashionCLIP image embeddings |

### 8.2 Evaluation data

The pipeline also returns:

```python
evaluation_data = {
    "search_queries": executed_queries,
    "retrieval_records": all_retrieved_images,
    "candidate_records": all_scored_records,
}
```

The candidate records include the original retrieval rank, FashionCLIP rank and similarity score.

These records support later comparison of original retrieval ordering against FashionCLIP reranking.

The pipeline's evaluation output is not itself a retrieval-quality score. Precision@K and NDCG@K require independently assigned relevance judgments.

## 9. Student 3 File-Based Handoff

The module uses `handoff.py` to create a file-based handoff compatible with Student 3's product retrieval adapter.

### 9.1 Required files

Each handoff contains:

```text
inspiration-handoffs/
└── <unique-request-id>/
    ├── phase_2_output.pt
    ├── expanded_fashion_context.txt
    ├── context.json
    └── model_info.json
```

The files are stored under the configured `STUDENT3_DATA_ROOT`.

The default data root is:

`artifacts/product-retrieval`

Each execution creates a unique directory to prevent accidental overwriting of another request's files.

### 9.2 Model metadata

`model_info.json` contains separate model profiles for context and image embeddings.

Each profile declares:

- Model ID.
- Model revision.
- Preprocessing identifier.
- Transformers version.
- Embedding dimension.
- L2 normalization.

Student 3 compares both profiles with its local `MODEL_IDENTITY`.

The adapter reports `declared_compatible` when the declared identities match.

This is a declaration-based compatibility check, not independent proof of identical preprocessing.

### 9.3 Handoff payload

The handoff function returns:

```python
{
    "upstream": {
        "pt": "inspiration-handoffs/<id>/phase_2_output.pt",
        "text": "inspiration-handoffs/<id>/expanded_fashion_context.txt",
        "context": "inspiration-handoffs/<id>/context.json",
        "model_info": "inspiration-handoffs/<id>/model_info.json",
    },
    "reference_mode": "imported",
}
```

These paths are relative to Student 3's configured data root.

Student 3's `search_products` tool accepts the dictionary as its payload and resolves the referenced files.

### 9.4 Imported embeddings

Student 3 supports two reference modes:

| Mode | Behavior |
|---|---|
| `recompute` | Recreates representations using Student 3's processing pipeline |
| `imported` | Uses the supplied vectors when model compatibility checks pass |

The Student 2 handoff uses `imported` mode.

Student 3's adapter validates tensor dimensions, finite values, nonzero norms, unique image IDs and vector ordering.

## 10. LangChain Integration

The shared agent is defined in:

`travel_agent/agent.py`

Student 2's LangChain tool is:

```python
@tool
def search_references(payload: dict) -> dict:
    return run(payload).model_dump(mode="json")
```

The tool invokes `travel_agent/inspiration/service.py`.

The service:

1. Receives Student 1's understanding output.
2. Checks downstream readiness and validates required inputs.
3. Converts Student 1 output into inspiration pipeline inputs.
4. Executes the FashionCLIP retrieval and ranking pipeline.
5. Generates the Student 3 file-based handoff.
6. Returns a `ModuleResult` containing the results and `product_handoff`.

The current service also returns JSON-compatible embedding lists. These are retained for compatibility and debugging, although the file-based handoff is preferable for downstream tensor transfer.

The shared agent registers `search_references` alongside the other student tools.

Tool registration does not guarantee execution order or automatic transfer of results. Reliable orchestration remains a shared integration responsibility.

## 15. Known Limitations and Pending Work

### 15.1 Retrieval limitations

- Unsplash search results may not always represent the requested clothing style accurately.
- Search quality depends on the generated queries and available Unsplash images.
- API rate limits constrain live retrieval testing.
- Image downloads may fail or become unavailable.
- Cosine similarity alone does not establish human-perceived relevance.

### 15.2 Model and preprocessing limitations

- Imported embedding compatibility currently relies on declared model metadata.
- The exact text and image preprocessing behavior must remain consistent between Student 2 and Student 3.
- Model checkpoint and dependency changes may require regenerating embeddings.

### 15.3 Agent integration limitations

- Full live Student 1 → Student 2 → Student 3 orchestration has not yet been verified.
- The central agent currently selects tools dynamically.
- Persistent session management and reliable cached-handoff reuse are not yet implemented.
- The current service still exposes embedding lists in addition to the file-based handoff.
- Downstream product availability, pricing and outfit feasibility are outside Student 2's scope.

### 15.4 Evaluation limitations

- Pipeline execution tests have passed.
- Retrieval-quality evaluation using independently judged relevance labels remains separate.
- Precision@K, NDCG@K and qualitative comparisons should be reported only after evaluation is performed.

## 16. Collaboration and Integration Notes

Student 2 owns the inspiration retrieval and ranking module.

Changes to shared agent orchestration, shared schemas, dependency files and CI configuration require review from affected team members.

The Student 2 → Student 3 interface uses the existing product retrieval upstream adapter rather than modifying Student 3's M1–M6 pipeline.

For a new user request, the inspiration module generates new embeddings and a new handoff.

For a refinement that does not change the inspiration context, the application may reuse a previously validated handoff. Such reuse requires session-state tracking and compatibility checks and is not yet guaranteed by the current implementation.
